# Глобальні канонічні правила сімейних подорожей
**Версія 1.0 — 08.11.2026.** Універсальні правила, незалежні від країни, круїзу та дат. Для наступних подорожей читати цей документ ПЕРЕД локальними правилами конкретного проєкту. Конкретні підтверджені факти та бронювання зберігати в окремому файлі подорожі.

## 1. Призначення
- Сімейний сайт — інструмент вибору, виконання плану й уникнення втрати вражень, а не каталог усіх можливостей.
- Не перевантажувати дні. Одна рекомендована програма, максимум одна справді змістовна альтернатива; погодні/логістичні резерви окремо. Рішення родини не підміняти автоматично.
- Показувати фото саме локації, опис враження, навігацію, реальний повний час, ціну, доступ і конкретну дію.

## 2. Сімейний профіль та інтереси
- Профіль учасників поточної поїздки: 3 дорослих, 1 дитина 10 років; один дорослий — особа з інвалідністю I групи; один із двох інших дорослих (дружина АБО повнолітній син) може бути супроводжуючим, якщо правила конкретного закладу передбачають таку пільгу. На наступній поїздці актуалізувати вік, склад і документи; не переносити автоматично вічні факти.
- Після першого представлення учасник може добровільно заповнити анкету; доступ до редагування завжди. Категорії: природа; панорами; гори/вулкани; сільські пейзажі; морські пейзажі; океан і пляжний відпочинок (окремо); тварини; спостереження за китами/дельфінами (окремо); аквапарки; атракціони; канатні дороги; музеї/історія; атмосферні міста/села; гастрономія; тихий відпочинок; активний відпочинок; прогулянки/походи; морські екскурсії. Розширювати відповідно до регіону.
- Шкала для кожної категорії: не цікавить / цікаво / дуже цікаво; окремий стан «не відповів». Тихий та активний відпочинок — незалежні інтереси, не взаємовиключні полюси. Додатково враховувати комфорт переїздів, пішого навантаження та бажаний темп.
- Інтереси — контекст рекомендацій, НЕ автоматичне рішення або рейтинг людини.

## 3. Сімейні голосування, ідеї, коментарі
- Голосування за справжні маршрутні альтернативи та окремі цікаві активності; кожен учасник має один актуальний голос на питання, може його змінювати.
- Зберігати на сервері: учасник, подорож/день, питання, варіант, вільний коментар із причиною або побажанням, час оновлення; за можливості історію змін. Коментарі не зводити до підрахунку голосів: використовувати в подальшому аналізі вподобань, суперечностей і компромісів, не вигадуючи мотивів.
- Нові ідеї мають статуси «запропоновано / обговорюємо / погоджено / відхилено». Голосування не змінює затверджений маршрут автоматично.
- Просте представлення на першому пристрої, локальне запам'ятовування браузером, можливість «Це не я»; новий браузер може потребувати повторного вибору учасника. Без обов'язкових паролів, пошти чи спеціальних програм. Не стверджувати, що локальний вибір забезпечує надійну автентифікацію.
- Для синхронізації — наявний за можливості Railway API/БД; перед реалізацією перевірити фактичні сервіси й доступ. Для аналізу ChatGPT потрібен окремий дозволений доступ до даних, а не просто існування БД.

## 4. Часова ціна та ризики
- Кожна суттєва локація має індикатор часу: ЗЕЛЕНИЙ — легко вписати; ЖОВТИЙ — потрібен компроміс; ЧЕРВОНИЙ — без вилучення/заміни іншої активності або зміни маршруту не поміщається. Червоний НЕ означає «нецікаво».
- Показувати ПОВНИЙ часовий бюджет: переїзд, паркування, черги, реєстрація/посадка, активність, повернення й резерв, а не лише тривалість екскурсії.
- Незалежно оцінювати логістичне відхилення і жорсткі обмеження (слоти, погода, час корабля/рейсу). Не приховувати різні ризики одним сумарним кольором.
- Для великої нової активності прямо відповідати: «Що доведеться скоротити або прибрати?»; не підміняти підтверджені сімейні пріоритети новими ідеями.

## 5. Квитки, слоти, доступ і компактні кнопки
- Для КОЖНОЇ суттєвої локації визначити: вільний доступ / квиток / попередня реєстрація / обов'язковий часовий слот / дозвіл / гід; чи можна купити на місці; ризик розпродажу; коли відкривається бронювання; дедлайн, правила скасування й резерв.
- Значки доступу окремо від індикатора часу: «квиток», «заздалегідь», «реєстрація/дозвіл», «без бронювання». Потреба у бронюванні і ФАКТ оформлення — різні поля. Стани: не оформлено / оформлено / підтверджено / недоступно; не вигадувати підтверджень.
- Біля кожної локації — КОМПАКТНА кнопка «Квитки» / «Бронювати» / «Реєстрація» з перевіреним ПРЯМИМ URL відповідної дії, а не довгий URL у тексті чи лише головна сторінка. За потреби додати окрему кнопку «Правила / пільги» і альтернативного продавця, якщо обґрунтовано.
- Єдиний список «Що забронювати до поїздки» з посиланнями, дедлайнами та фактичним статусом; пріоритет критичних слотів. Якщо URL не перевірено, чесно позначити; не вигадувати посилань.

## 6. Інвалідність, супровід і купівля квитків — ОСНОВНИЙ ПРИНЦИП
- Мета: НЕ втратити важливу локацію, але максимально використати реально доступні пільги. Практичний досвід мандрівника: українське посвідчення про інвалідність багаторазово приймали в касах; відмов через «неєвропейський зразок» у його досвіді не було. Не вважати українські документи перешкодою за замовчуванням; водночас не гарантувати прийняття в кожному закладі.
- Перевіряти окремо: (а) пільгу для особи з інвалідністю; (б) пільгу для ОДНОГО супроводжуючого, якщо передбачено; (в) дитячий тариф; (г) звичайний тариф другого дорослого. Не приписувати автоматично пільгу обом супроводжуючим. Для кожної наступної поїздки актуалізувати склад.
- Якщо онлайн є пільговий тариф, а система не вимагає завантаження документів — пріоритетно оформлювати відповідну пільгову категорію онлайн, за умови відповідності опублікованим правилам; документ показати при вході. Якщо онлайн приймає наявний український документ — також пріоритет онлайн.
- Якщо пільга онлайн не застосовується або завантаження українського документа технічно неможливе — ПЕРЕВАГА купівлі у касі, де можна особисто звернутися по пільгу, НАСКІЛЬКИ ЦЕ БЕЗПЕЧНО ДЛЯ ДОСТУПНОСТІ КВИТКІВ.
- Навіть якщо сайт не описує пільги, на касі вона може існувати. «Не згадано онлайн» НЕ означає «пільги немає».
- Якщо сторінка не відкрилася, умови не вдалося проаналізувати або пільгову категорію під час перевірки не виявлено, НЕ стверджувати «пільг немає». Показати зірочку (*) і точний зміст невизначеності, наприклад: «* Під час перевірки онлайн-бронювання пільгового тарифу не виявлено / сторінка недоступна для перевірки. Якщо пільга є, перевір, будь ласка, самостійно — [компактна кнопка “Квитки”]». Розрізняти «не побачив» і «не зміг перевірити».
- Якщо часові слоти дефіцитні або існує ризик не потрапити до важливої локації, НЕ ризикувати нею заради непідтвердженої економії: своєчасно бронювати доступний тариф, навіть ПОВНИЙ, якщо це необхідно для гарантованого входу. За можливості перед цим швидко уточнити пільгове резервування через адміністрацію, але не пропускати дедлайн.
- У картці показувати рекомендований канал купівлі (пільговий онлайн / каса / уточнення / повний онлайн через дефіцит), перевірені умови й документи, прямі кнопки, реальну або умовну суму за склад родини. Не видавати припущення за підтверджену знижку.
- Відсутність онлайн-завантаження документа не скасовує перевірки права на тариф на вході. Не передавати копії документів або приватні дані без явного дозволу.
